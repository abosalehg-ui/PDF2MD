## 1. نظرة عامة سريعة

**PDF2MD** أداة تستخرج نصًّا عربيًّا سليمًا من ملفات PDF المصدَّرة من Word ثم المعالَجة عبر محرّك Quartz — وهي ملفات تحمل خللًا في خريطة `ToUnicode` يجعل الرباطات العربية تُخزَّن معكوسة (`املادة` بدل `المادة`) — وتحوّلها إلى Markdown منظَّم بعناوين وفقرات وجداول وحواشٍ وفهرس. الإصلاح هندسي بحت: إحداثيات الحروف وبكسلات الصفحة، بلا قاموس ولا تخمين لغوي.

البنية أربع طبقات تحتها ثلاث واجهات: `core.py` (الاستخراج الهندسي) و`structure.py` (البنية والتصنيف) و`ocr.py` (رصد الطبقة المعطوبة والسقوط إلى Tesseract) و`common.py` (المشترك)، وفوقها `cli.py` و`gui.py` (PyQt6، مقسومة إلى لوحات وخيوط وهوية) و`web.py` الذي يعمل بلا تعديل داخل المتصفّح فوق Pyodide.

### 2.4 معالجة الأخطاء والحالات الحدّية — **7/10**

ما هو قوي: كلمة المرور تُرفض برسالة، نطاق الصفحات يُشرح كل انحراف فيه، فشل ملف في الدفعة لا يُسقطها، الاستثناء لا يعبر حدّ Pyodide، ومهلة الصمت في `engine.js` تحرس الخيط الميت. ثلاث ثغرات بقيت:

**(أ) مسار الـOCR بلا سقف بكسلات — النظير المفقود لإصلاح المراجعة الماضية.**

`ocr.py` — في `page_lines()`:
```python
scale = dpi / 72.0
png = page.get_pixmap(matrix=fitz.Matrix(scale, scale)).tobytes("png")
```
`core.ink_map` يُنزّل الدقة تلقائيًا فوق `INK_MAX_PIXELS` (٤٠ مليون بكسل) — وهو إصلاح البند الأول من المراجعة الثانية. لكن مسار الـOCR يرسم الصفحة بـ٣٠٠ نقطة/بوصة **بلا أي سقف**. القياس (بحقن `get_pixmap` وهمي على صفحة ١٤٤٠٠×١٤٤٠٠ نقطة، وهي مشروعة في مواصفة PDF):

| المسار | معامل التكبير | البكسلات | الذاكرة التقريبية |
|---|---|---|---|
| `core.ink_map` | ٠٫٠٤٤ | ٤٠ مليون | ٤٠ م.ب |
| `ocr.page_lines` | **٤٫١٦٧** | **٣٫٦ مليار** | **~١٠٫٨ غ.ب** (RGB) + نسخة PNG |

الشرط لبلوغه: Tesseract مثبَّت، وصفحة يحكم عليها `page_verdict` بأنها ممسوحة — أي صورة تغطي ١٠٪ من صفحة عملاقة خالية من النص. ملف بحجم كيلوبايت يقتل العملية على سطح المكتب وسطر الأوامر. الويب في مأمن لأن `web.py` يجبر `ocr = "never"`.

البديل: استخراج منطق السقف من `ink_map` إلى دالّة `core.safe_zoom(page, dpi, max_pixels)` تستعملها الاثنتان، مع سقف أعلى للـOCR (نحو ٨٠ مليونًا، لأن الدقة هناك تُهمّ) وتحذير في السجل عند التنزيل.

ويُضاف إليه أن `--ocr-dpi` مسقوف من الأسفل فقط:

`cli.py` — في `options_from()`:
```python
if opt.ocr_dpi < 200:
    sys.exit("دقة OCR أقل من 200 تُتلف نقاط الحروف العربية.")
```
`--ocr-dpi 100000` يمرّ. حدّ أعلى (٦٠٠) يكفي، والسقف أعلاه يحمي على كل حال.

**(ب) سباق حالة في `Engine.run` — الحارس موجود لكنه يفحص قبل `await`.**

`web/js/engine.js` — في `run()`:
```js
await this.start();
if (this.pending) throw new Error('المحرّك مشغول بعملية أخرى.');
const id = (this.seq += 1);
const buffer = await file.arrayBuffer();     // ← نقطة تسليم: نداءٌ ثانٍ يمرّ من الفحص هنا
return new Promise((resolve, reject) => {
  this.pending = { id, resolve, reject };
```
نُفّذ على Node بخيط وهمي: نداءان متزامنان لـ`convert()` بلا انتظار بينهما → الثاني يكتب فوق `pending` الأول، ثم تصل نتيجة الأول برقم لا يطابق فتُهمَل ويُصفَّر `pending`، وتصل نتيجة الثاني ولا منتظِر لها. **الوعدان يعلَّقان إلى الأبد** — لا خطأ ولا مهلة، لأن مهلة الصمت تُلغى مع تصفير `pending`.

الاختبار `لا مهمتان في وقت واحد` في `engine.test.mjs` ينتظر ٥ مللي ثانية بين النداءين، فيختبر الحالة السهلة ويترك السباق. الواجهة الحالية لا تبلغه لأن `state.running` يُضبط قبل أول `await`، فالخطر في **عقد** المحرّك لا في الصفحة اليوم. البديل: حجز `pending` قبل قراءة الملف:
```js
if (this.pending) throw new Error('المحرّك مشغول بعملية أخرى.');
this.pending = { id, resolve: null, reject: null };   // حجز فوري
const buffer = await file.arrayBuffer();
```
مع تحديث الاختبار ليستدعي النداءين بلا انتظار.

**(ج) `-o ملف.md` مع أكثر من ملف يصير مجلدًا اسمه `ملف.md` بصمت.**

`common.py` — في `out_path_for()`:
```python
named_file = bool(out) and os.path.splitext(out)[1].lower() == ".md"
if out and not many and not os.path.isdir(out) and named_file:
    return out
folder = out if out else (...)
```
قِيس: `out_path_for("a.pdf", "out.md", many=True)` → `out.md/a.md`. README يقول «المسار المنتهي بـ`.md` يُعدّ ملفًا... القاعدة واحدة سواء حوّلت ملفًا أو دفعة» — والكود يخالفه في الدفعة. البديل: `sys.exit("‎-o يشير إلى ملف واحد بينما الدخل عدة ملفات")` في `cli.py` قبل الحلقة.

**(د) إغلاق النافذة أثناء صفحة OCR.**

`gui.py` — في `closeEvent()`:
```python
self._cancel.set()
for w in list(self._workers):
    w.wait(10000)
```
الإلغاء يُفحص بين الصفحات، لكن `ocr._tsv` يمنح Tesseract ١٢٠ ثانية للصفحة الواحدة. صفحة كثيفة تتجاوز عشر ثوانٍ → تُقبل `closeEvent` والخيط لا يزال يعمل → إتلاف `QThread` وهو يعمل، وهو ما يحذّر منه التعليق في `__init__` نفسه. البديل: `wait()` بلا مهلة بعد الإلغاء مع مؤشّر «جارٍ الإيقاف» في شريط الحالة، أو تمرير `cancel` إلى `_tsv` ليقتل العملية الفرعية.

### 2.5 الأداء واستهلاك الموارد — **8/10**

المقيس على ٤٠ صفحة: `auto` و`never` متطابقان (٠٫٣٨ ث) — ضريبة حكم الـOCR زالت فعلًا كما ادّعت المراجعة الماضية. فحص الحبر يضيف ٤٠٪ لا ٣× كما تقول التسمية في الواجهات («أبطأ ٣×»)؛ الرقم من قياس قديم على ملفات حقيقية أكثف، فليس خطأً لكنه غير محدَّث.

الحلقات على الصفحة الواحدة خطّية أو شبه خطّية (`_group_segments` تفحص كل جزء ضد المجموعات القائمة؛ الصفحة العادية بضع عشرات). الذاكرة: أسطر المستند كله تُحمَّل قبل البناء — حدّ موثّق. مسار الـOCR بلا سقف (٢٫٤ أ) هو الثغرة الوحيدة الحقيقية.

### 2.6 الاختبارات — **8/10**

### ما لا يحتاج لمسًا

- `tools/fetch_web_runtime.py` و`build_site.py` و`serve.py`: بصمات، واستخراج آمن، ومهلة شبكة، وربط على `127.0.0.1` — لا ملاحظة.
- `zip.js`: بنية ZIP صحيحة، وراية UTF-8، وفضّ الأسماء المكرّرة، ويُفكّه بايثون في الاختبار.
- `web.py`: العقد مع جافاسكربت نصّ JSON خالص، والاستثناء لا يعبر الحدّ، والقيم تُقصّ لا تُصدَّق.
- `core.py`: ٩٨٪ تغطية، والثوابت مقيسة ومشروحة، وسقف الرسم في `ink_map` هو النموذج الذي يحتاجه البند ١.
